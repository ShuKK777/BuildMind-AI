## 判断

Valdrada 适合成为智策与智绘共用的三维能力来源。它已有独立的程序化建筑生成库、可漫游的城市客户端、车道/人行道仿真、光照天气以及固定步长镜头录制。与当前 Three.js 演示的技术路线一致，值得复用源码，而不只借鉴截图。

0.2 的产品目标是：**把现有打印沙盘扩展成可漫游、可比较、可修改的滨水街区，让规划与建筑设计发生在同一个场景中。**

我们负责场景定义、产品交互、方案数据、地块规则、A02 编辑、后续多模态工具编排与工程知识服务。上游提供可借鉴或移植的几何、渲染与场景技术。引用开源底座时保留作者与来源，研发说明具体写清我们新增的能力。

## 模块一：智策

第一轮围绕“看见方案差异”做真实交互：

1. 保留建设前、一期、建设后的故事，增加鸟瞰、街道漫游、滨水观察三个视角。
2. 用参数化住宅、办公与商业建筑丰富周边，补充道路、人行道、树木、路灯、滨水空间和轻量车辆/行人。
3. 提供两到三套可比较的街区情景：如紧凑商务、宜居混合、滨水花园。情景记录建筑、用途、层数、绿化和道路设置。
4. 从场景数据计算建筑数量、用途分布及概念体量面积估算；指标随情景更新。需要外部证据的人口、经济与政策效果另由后续模型提供。
5. 智绘应用的 A02 方案直接成为当前规划情景中的建筑状态。

车流/人流首先承担可视化演示。它们不能直接充当北都规划优化、产业发展或社会行为评估模型；后续通过适配接口接入我们的城市仿真与规划反馈逻辑。

## 模块二：智绘

保留“先给几版，选中后逐步修改”的流程：

- **流线曲面**：保留并扩展本项目的曲面体量生成，接入更好的材质、裙房与构件表现。上游标准建筑库不能直接替代这一类自由曲面设计。
- **玻璃双塔**：复用玻璃塔的幕墙、裙房与 twin 体量思路，暴露双塔高差、塔间距、连廊和立面参数。
- **层叠花园**：复用 stepped 体量和退台构件思路，另外加入我们可控的退台曲线、花园、绿化与空间连接。
- A02 保持稳定 ID 和地块锚点；每个候选保存风格、种子、参数、构件与来源。选择、撤销、恢复和应用都操作同一份方案数据。
- 原始建筑、参考条件、候选方案与修改历史形成数据接口，便于后续接入图像理解、生成、建模及渲染工具。

本次核对到的上游生成器是**规则和参数驱动**的建筑生成器。任意参考图到建筑的多模态生成，以及面向规划目标的自动优化，仍需要由我们的编排与模型服务实现。

## 独立验证结果与接入细节

已用 Three.js **0.185.1** 和 Node Canvas 在 CPU 环境构建 7 组模型，包括玻璃塔四组、混合建筑、deco 退台建筑及花园公寓。结果见 [valdrada-geometry-checks.json](valdrada-geometry-checks.json)。输入均为宽 24、深 25、恒等坐标矩阵、商业底层开启的展示地块。

验证通过：几何坐标有限、同种子重建哈希一致、换种子改变几何、提高请求层数会提高玻璃塔的返回高度。该结果只证明生成库可独立工作；没有做 GPU 着色、阴影、材质视觉或实际设备帧率验收。

接入时必须处理这些已观察到的差异：

- 16 层、seed 9 的玻璃塔返回高度约 **55.11 m**，实际几何包围盒高度约 **62.52 m**。正文高度与屋顶设备包络应分别记录。
- 输入 24×25 的地块，几何包络可能更宽、更深（阳台、檐口、外部构件）。替换 A02 前检查地块、道路及周边碰撞，不能假定输入宽深等于严格边界。
- `glasstower` 的体量分支目前由种子抽样，明确的“双塔/退台”选择需要适配成显式参数。
- 生成器带有纽约的层高、栏杆与街道习惯。用于北都概念设计时转换为设计参数，不能把这些默认值当成本地规范依据。
- Batcher 会按材质合并几何；可编辑对象需要独立组或实例到对象 ID 的映射，保留 A02 的选取和修改能力。
- 同一前端使用单一 Three.js 版本。0.1 当前使用 r180；0.2 单独固定 r185.1，并逐项验证 API/着色器，避免混用两套 Three.js。
- 完整的城市渲染器、交通和行人含纽约特例与模块级状态，需按接口拆接；不宜把整个 `client/` 当成零改动通用 SDK。

## 离线与场景数据

首轮采用本地的北都滨水**概念街区**与打印模型布局，按需复用生成库，打包全部纹理、字体、解码器和模型。上游完整纽约二进制资产包按其 BUILDING.md 约为 3.1 GB，未包含在源码 checkout；本次验证没有依赖它。

打印模型毫米与新街区米制场景分开标明单位与转换约定。没有真实测绘/比例依据时，不把 150 mm 打印底板或 72 mm 地标高度换算成官方实际地理尺寸。纽约投影锚点也不直接用于香港场景。

资源按依赖清单在构建阶段收齐，运行阶段由本机服务提供。画质设置“演示/标准/兼容”，目标设备帧率通过实测确定；保留 0.1 入口与简化几何作为演示退路。

## 第一轮开发顺序与验收

1. **共同场景底座**：建立对象/地块/方案结构和坐标约定；复用生成器；保留 A02 选择、恢复与来源标识。
2. **观感与漫游**：透视鸟瞰、地面视角、天空、太阳、玻璃、阴影与轻量环境细节；在目标设备验收。
3. **方案比较与编辑**：三种地标表达、参数预览、撤销/保存/应用；智策与智绘状态同步。
4. **街区情景与生活**：建设阶段、用途情景、轻量路网和车辆/行人；指标来自场景模型并标明口径。
5. **演示交付**：同一场景时间线驱动 45 秒播放与录制；中英切换；断网启动验证；0.1/0.2 都可独立进入。

第一轮可验收：在一个完整离线街区内，从鸟瞰进入街道，切换规划情景，选择最高地标，比较三类建筑并修改参数，应用回同一场景，最后一键播放。智管沿用现有文档审查入口，后续继续接入真实检索与审查服务。
